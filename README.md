# Logus Nova — кабинет клиента

PWA-кабинет для конечного клиента логистики: собирает заказы с разных электронных
площадок (**ATI.SU**, **Loginet**, **своя площадка**) в единый список и даёт клиенту
видеть и вести перевозки в одном окне — без звонков логистам и ручного сбора статусов.

Кабинет **не заменяет площадки**, а работает поверх них: слой адаптеров приводит
заказы к единой (канонической) модели, а клиент управляет процессом из одного
интерфейса. Проект — отборочная работа чемпионата Logus Nova.

## Возможности

- **Единый список заказов** со всех подключённых площадок с фильтрами (площадка,
  статус) и поиском по номеру, городам, грузу и перевозчику.
- **Сводка** по статусам: в пути, проблемы, доставлено, ожидает решения.
- **Карточка заказа**: маршрут, груз, стоимость, перевозчик, документы и история статуса.
- **Действия клиента**: подтвердить, запросить изменение, сообщить о проблеме,
  урегулировать, подтвердить получение, отменить, загрузить документ.
- **Уведомления** о значимых событиях по заказам.
- **Тёмная и светлая темы**, русский интерфейс, мобильный-первый дизайн.
- **PWA**: установка на устройство и офлайн-оболочка (service worker).
- **Отказоустойчивая загрузка** интерфейса: даже при сбое источника показывается
  понятная заглушка с кнопкой «Повторить», а не «вечный спиннер».

## Стек

- **Фронтенд:** React + TypeScript (strict) + Vite, `@tanstack/react-query`.
- **Бэкенд:** PHP 8, один файл `api.php` (без фреймворка), сессии, файловый кэш.
- **Данные:** адаптеры площадок реализуют интерфейс `PlatformAdapter`; на отборочном
  этапе наполнены реалистичными mock-данными (`private/seed.php`).
- **Стандарт разработки:** [`docs/DEVELOPMENT.md`](docs/DEVELOPMENT.md).

## Требования

- Node.js ≥ 20 (проверено на 22)
- PHP ≥ 8.1 (проверено на 8.5), расширения `session`, `json`
- Chrome/Chromium — только для e2e-тестов

## Быстрый старт

### 1. Установка

```bash
npm install
```

### 2. Продовый режим (собранная сборка, отдаёт PHP)

```bash
npm run build            # tsc + vite + иконки + shell + презентация
php -S 127.0.0.1:8090    # запускать из корня репозитория
```

Откройте <http://127.0.0.1:8090/>.

### 3. Режим разработки (hot reload)

```bash
npm run dev:php          # терминал 1: PHP на 127.0.0.1:8090
npm run dev              # терминал 2: Vite на http://localhost:5173
```

Откройте <http://localhost:5173/> — запросы `/api.php` Vite проксирует на PHP-сервер
(см. `web/vite.config.ts`).

### 4. Вход

Демонстрационные учётные данные: логин **`demo`**, пароль **`logus2026`**.

## Секреты и переменные окружения

`private/secrets.php` содержит учётные данные и **не попадает в git**. Для локального
запуска:

```bash
cp private/secrets.example.php private/secrets.php
# демо-значения demo / logus2026 уже прописаны
```

Свой пароль — по bcrypt-хэшу:

```bash
php scripts/make-hash.php 'ваш-пароль'
# вставьте результат в private/secrets.php → 'password_hash' => '...'
```

Переменные окружения имеют приоритет над файлом (удобно в CI/контейнерах):

| Переменная             | Назначение                                                        |
| ---------------------- | ----------------------------------------------------------------- |
| `LOGUS_USER`           | Логин клиента                                                     |
| `LOGUS_PASSWORD`       | Пароль в открытом виде (для разработки)                           |
| `LOGUS_PASSWORD_HASH`  | bcrypt-хэш пароля (приоритетнее `LOGUS_PASSWORD`)                 |
| `LOGUS_MOCK_MODE`      | Режим мок-площадок: `normal` \| `empty` \| `error` \| `slow`      |
| `PHP_TARGET`           | Адрес PHP-сервера для прокси Vite (по умолчанию `http://localhost:8090`) |
| `CHROME_BIN`           | Путь к Chrome/Chromium для e2e-тестов                             |

## Тесты

Раннер поднимает PHP-сервер с нужным режимом мок-площадок и headless Chrome (CDP,
порт 9222), затем прогоняет сценарии:

```bash
npm test                  # все сценарии
node tests/run.mjs base slow    # только выбранные
node tests/run.mjs shell        # юнит-тесты загрузчика, без браузера
node tests/run.mjs --list       # список сценариев
```

| Сценарий | Что проверяется                                                        |
| -------- | ---------------------------------------------------------------------- |
| `shell`  | 14 проверок shell-загрузчика (цепочка источников, таймауты, заглушка)  |
| `base`   | Вход, список, карточка, действия, поиск, уведомления, тема             |
| `empty`  | Пустой ответ площадок → состояние «пусто» без падения                  |
| `error`  | Недоступность площадок → деградация без ошибок в консоли              |
| `slow`   | Медленная площадка → скелетоны, затем загрузка                        |
| `mobile` | Вьюпорт 390px: нет горизонтального переполнения, диалог вписывается    |

Секреты на прогон берутся из `tests/secrets/base.php` и временно копируются в
`private/secrets.php`; исходный файл восстанавливается после тестов.

## API

Все запросы — к `api.php?action=...`. Ответы и ошибки в формате JSON; ошибки —
конверт `{"error":{"code","message","details"}}`.

| Action           | Метод | Доступ  | Назначение                                             |
| ---------------- | ----- | ------- | ------------------------------------------------------ |
| `session`        | GET   | —       | Текущая сессия (быстрая, без обращения к площадкам)    |
| `login`          | POST  | —       | Вход по логину и паролю                                |
| `logout`         | POST  | —       | Выход                                                  |
| `orders`         | GET   | клиент  | Список заказов: `platform`, `status`, `q`, `page`, `limit` |
| `order`          | GET   | клиент  | Карточка одного заказа: `id`                           |
| `order_action`   | POST  | клиент  | Действие по заказу: `id`, `action`, `note`, `docType`  |
| `notifications`  | GET   | клиент  | Лента уведомлений и число непрочитанных                |
| `platforms`      | GET   | клиент  | Подключённые площадки и число заказов                  |
| `sync`           | POST  | клиент  | Синхронизация с площадками                             |
| `asset`          | GET   | —       | Отдача бандла из кэша (для shell-загрузчика)           |
| `diag`           | POST  | —       | Приём диагностического маячка от клиента               |

Значения `action` для `order_action`: `confirm`, `reject`, `request_change`,
`report_problem`, `resolve_problem`, `mark_received`, `upload_doc`, а также
`ack_notification` (отметить уведомление прочитанным).

### Статусы заказа

`created → carrier_assigned → confirmed → loading → in_transit → unloading → delivered → closed`,
а также `cancelled` и `problem`.

## Отказоустойчивая загрузка

В `index.html` **нет тега `<script src>` основного бандла** — это защищает от
«вечной загрузки» в Яндекс.Браузере, когда скрипт не шлёт ни `load`, ни `error`.
Загрузчик (`web/shell-runtime.js`) сам перебирает источники по цепочке:

1. локальная копия бандла в `localStorage` (мгновенно);
2. `api.php?action=asset` (серверная отдача из кэша);
3. статика `./assets/app-*.js`.

У каждого шага есть таймаут на заголовки и отдельно на тело ответа, сверху — общий
сторож прогресса. Итог всегда определён: приложение загружено **или** заглушка с
кнопкой «Повторить». Подробности — в [`docs/DEVELOPMENT.md`](docs/DEVELOPMENT.md) §3.

## Презентация

Презентация на reveal.js собирается в `presentation/` и работает офлайн (без CDN):

```bash
npm run build:pres
```

Откройте `presentation/index.html`. Для PDF — добавьте `?print-pdf` и сохраните
через «Печать → Сохранить как PDF».

## Деплой (Apache)

1. Соберите артефакты: `npm install && npm run build`. В webroot положите:
   `index.html`, `assets/`, `presentation/`, `api.php`, `sw.js`, `site.webmanifest`,
   иконки, `.htaccess` и каталог `private/`.
2. Секреты: `cp private/secrets.example.php private/secrets.php` и заполните.
3. Права: `private/` (его подкаталоги `cache/`, `asset-cache/`, `diag/` — на запись)
   — `0700`, `secrets.php` — `0600`, владелец — пользователь веб-сервера.
4. Каталог **`private/` физически лежит рядом с `api.php`** (пути в коде идут от
   `__DIR__`), поэтому доступ закрывается `private/.htaccess` (`Require all denied`)
   **или** блоком `<Directory .../private> Require all denied </Directory>` в vhost.
   Для `.htaccess` нужен `AllowOverride` ≥ `FileInfo` (`AuthConfig` для запрета).
5. `AddType application/manifest+json .webmanifest`; модуль `mod_headers` обязателен.
   `.htaccess` отключает переупаковку/сжатие JS/CSS (критично для Яндекс.Браузера)
   и выставляет `Service-Worker-Allowed: /` для `sw.js`.
6. HTTPS обязателен для service worker и установки PWA (исключение — `localhost`).

### Если curl быстрый, а браузер «зависает» на загрузке

Загрузчик перебирает источники `localStorage → api.php?action=asset → статика (fetch)
→ <script src>`. Последний, нативный `<script src>`, не использует `fetch` и чтение
потока и выручает, если посредник/старый движок «подвешивает» тело fetch-ответа.
Проверка сервера:

```bash
curl -sSI https://host/.../sw.js | grep -i service-worker
curl -s -o /dev/null -w '%{http_code} %{size_download} %{time_total}\n' \
  https://host/.../assets/app-<hash>.js
curl -sS 'https://host/.../api.php?action=asset&f=app-<hash>.js' | head -c 80
```

Если curl отдаёт файл мгновенно, а браузер нет — дело в клиенте/посреднике; нативный
фолбэк должен закрыть сценарий. Старый service worker можно сбросить в DevTools →
Application → Service Workers → Unregister.

## Ограничения отборочного этапа

- Площадки эмулируются mock-адаптерами — реальные коннекторы подключаются заменой
  `fetchOrders()` без изменения остального кода.
- Один тип пользователя — конечный клиент.
- Оплата и web-push — задел на будущее, в текущей версии не реализованы.
